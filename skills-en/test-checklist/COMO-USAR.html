🧪 Roteiro de Teste HTML

A sua skill /test-checklist: monta uma lista de testes manuais em HTML, com botão Salvar, para qualquer projeto.

1O que ela faz

Você pede ao Claude e ele:

  1. Lê o projeto que está aberto: as regras, a especificação, o histórico do git e, se houver, o sistema de tarefas (opcional, só leitura). Descobre em quais plataformas ele roda (iOS, Android, Web) e se tem variações (por exemplo, um jogo com uma trilha da Floresta e outra do Oceano).
  2. Decide o que precisa ser testado à mão e te mostra a lista antes de montar. Um card que vale para todas as variações aparece uma vez só.
  3. Se o app puder rodar aqui (emulador, simulador ou navegador), oferece mandar o QA independente testar, uma plataforma por vez. O que o QA viu entra no card, com prints.
  4. Depois, o Auditor confere só os cards que o QA aprovou: vê se o trabalho seguiu as regras do projeto (issue, branch, commits). Se o QA ou o Auditor reprovar, quem programa corrige, o QA testa de novo e o Auditor revisa de novo. Um card só fica verde quando os dois aprovam.
  5. Cada card tem três colunas: QA (Passou / Falhou), Auditor (Passou / Falhou, que só libera depois que o QA aprova) e Não testado. QA aprovou e falta o Auditor: o card fica azul. O Auditor reprovou: fica vermelho e mostra "QA aprovou · Auditor reprovou", com o motivo na nota.
  6. Quando todos os cards estão verdes, ela avisa, mas quem decide se o projeto acabou é o dev.
  7. Cria um HTML só por produto, com um card por teste: "Como testar", "Passa se", os botões Passou / Falhou / Não testado e uma nota. No topo você escolhe a plataforma, a rodada e o que está jogando, e troca entre português/inglês e claro/escuro.

Rodadas. Rodou a skill de novo depois de terminar mais uma parte do projeto? Ela não cria outro arquivo: acrescenta uma rodada nova no mesmo HTML, com os cards novos e os que falharam antes. As marcações que você salvou nunca são apagadas (e antes de mexer ela guarda uma cópia em ~/Ferramentas/html-salvavel/backups/).

Card aprovado não é retestado, a não ser que o dev mexa nele, ou num card ligado a ele (mexer em A pode quebrar B). Esses voltam com o aviso "↻ Alterado" ou "↻ Ligado a…".

Cada plataforma tem as suas marcações: passar no Android não marca o iOS. A aba Resultado mostra as plataformas lado a lado.

BDD do projeto. Se o projeto tiver uma pasta BDD/ (feita à mão ou pela skill /bdd-first), o roteiro mostra no topo o link "📘 Ver o BDD deste projeto", e cada card leva aos cenários Dado / Quando / Então que ele confere. O BDD diz o que o produto deve fazer; o roteiro guarda se alguém conferiu.

A janela de escolha. Toda vez que você chama a skill, ela abre uma janela (no Mac, um popup) com a família inteira: esta skill, a /bdd-first e as cinco de conversão iPhone ⇄ Android. Cada uma mostra se está instalada, faltando ou desatualizada. Nada é instalado sem você marcar.

💡 Card que passou com nota fica âmbar ("⚠️ Passou c/ nota"), para não passar despercebido.

2Usar num projeto deste Mac

Não precisa instalar nada: ela já vale para todos os projetos deste Mac.

  1. Abra o Claude Code na pasta do projeto.
  2. Digite /test-checklist, ou escreva algo como "monta o roteiro de teste".
  3. Responda às perguntas do Claude (uma de cada vez) e aprove a lista de cards.
  4. Quando o HTML estiver pronto, dê dois cliques em abrir-html-salvavel.command, que fica na mesma pasta do HTML.
Primeira vez num Mac: o macOS pode bloquear o atalho. Clique com o botão direito nele › Abrir › Abrir. Só é preciso uma vez.
"Só leitura" no topo da página? O HTML foi aberto com dois cliques no próprio arquivo, ou a janela do Terminal foi fechada. Abra sempre pelo atalho e deixe o Terminal aberto enquanto testa.

3Instalar em outro Mac

  1. Recebeu o test-checklist.zip? Dê dois cliques nele: aparece uma pasta chamada test-checklist.
  2. Abra o Finder, aperte ⌘ ⇧ G, cole ~/.claude/skills/ e aperte Enter.
    Se aparecer que a pasta não existe, crie-a: no Terminal, mkdir -p ~/.claude/skills.
  3. Arraste a pasta test-checklist para dentro de skills. O nome precisa ser exatamente esse, porque é o nome do comando.
  4. No Terminal, confira se o Python existe: python3 --version. Se o macOS oferecer instalar, aceite.
  5. Abra o Claude Code em qualquer projeto e digite /test-checklist. Na primeira vez, o Claude pergunta como você gostaria de ser chamado (o nome fica guardado em ~/Ferramentas/html-salvavel/nome.txt) e oferece instalar o resto, perguntando antes de cada coisa:
    • a ferramenta de salvar, em ~/Ferramentas/html-salvavel/;
    • os agentes QA e Auditor, se você ainda não tiver (depois, reabra o Claude Code);
    • o app Abrir HTML Salvável, com ícone próprio, em ~/Applications. Arraste ele para o Dock.
💡 O app do Dock: clique nele, escolha a pasta do projeto que tem o HTML de teste e pronto: abre o Terminal (deixe aberto) e o navegador com a lista. Da próxima vez ele mostra a lista dos últimos projetos. Dá para ter dois projetos abertos ao mesmo tempo: cada um fica na sua janela do Terminal. Se o macOS pedir para o app controlar o Terminal, clique em OK.

4Deixar só num projeto (opcional)

Se quiser que a skill funcione apenas num projeto, cole a pasta test-checklist dentro de <projeto>/.claude/skills/, em vez de na pasta pessoal.

Cuidado em projetos de empresa: o que fica dentro do projeto pode acabar indo para o repositório da empresa. Se a skill é sua, prefira a instalação pessoal (passo 3).

🧪 Test Checklist HTML

Your /test-checklist skill ("test checklist"): builds a list of manual tests in HTML, with a Save button, for any project.

1What it does

You ask Claude and it:

  1. Reads the open project: the rules, the specification, the git history and, if there is one, the task tracker (optional, read-only). It finds out which platforms it runs on (iOS, Android, Web) and whether it has variants (for example, a game with a Forest trail and an Ocean trail).
  2. Decides what must be tested by hand and shows you the list before building it. A card valid for every variant shows up only once.
  3. If the app can run here (emulator, simulator or browser), it offers to have the independent QA test it, one platform at a time. What the QA saw goes into the card, with screenshots.
  4. Then the Auditor checks only the cards the QA passed: whether the work followed the project's rules (issue, branch, commits). If the QA or the Auditor rejects, the developer fixes it, the QA tests again and the Auditor reviews again. A card only turns green when both pass it.
  5. Each card has three columns: QA (Passed / Failed), Auditor (Passed / Failed, only open once the QA passes) and Not tested. QA passed and the Auditor is pending: the card turns blue. The Auditor rejected: it turns red and shows "QA passed · Auditor rejected", with the reason in the note.
  6. When every card is green it tells you, but the developer decides whether the project is finished.
  7. Builds one HTML per product, with one card per test: "How to test", "Passes if", the Passed / Failed / Not tested buttons and a note. At the top you pick the platform, the round and what you are playing, and switch between Portuguese/English and light/dark.

Rounds. Ran the skill again after finishing another part of the project? It does not create another file: it adds a new round to the same HTML, with the new cards and the ones that failed before. The marks you saved are never erased (and before touching anything it keeps a copy in ~/Ferramentas/html-salvavel/backups/).

A passed card is not retested, unless the developer changes it, or a card linked to it (changing A can break B). Those come back with "↻ Changed" or "↻ Linked to…".

Each platform has its own marks: passing on Android does not mark iOS. The Result tab shows the platforms side by side.

The project's BDD. If the project has a BDD/ folder (made by hand or by the /bdd-first skill), the checklist shows "📘 See this project's BDD" at the top, and each card links to the Given / When / Then scenarios it checks. The BDD says what the product must do; the checklist keeps whether someone checked it.

The choice window. Every time you call the skill, it opens a window (on a Mac, a popup) with the whole family: this skill, /bdd-first and the five iPhone ⇄ Android conversion skills. Each one shows whether it is installed, missing or outdated. Nothing is installed unless you tick it.

💡 A card that passed with a note turns amber ("⚠️ Passed with note"), so it does not go unnoticed.

2Use it in a project on this Mac

Nothing to install: it already works in every project on this Mac.

  1. Open Claude Code in the project folder.
  2. Type /test-checklist, or write something like "build the test checklist".
  3. Answer Claude's questions (one at a time) and approve the list of cards.
  4. When the HTML is ready, double-click abrir-html-salvavel.command, in the same folder as the HTML.
First time on a Mac: macOS may block the shortcut. Right-click it › Open › Open. Only needed once.
"Read-only" at the top of the page? The HTML was opened by double-clicking the file itself, or the Terminal window was closed. Always open it through the shortcut and leave the Terminal open while testing.

3Install on another Mac

  1. Got test-checklist.zip? Double-click it: a folder called test-checklist appears.
  2. Open Finder, press ⌘ ⇧ G, paste ~/.claude/skills/ and press Enter.
    If it says the folder does not exist, create it: in Terminal, mkdir -p ~/.claude/skills.
  3. Drag the test-checklist folder into skills. The name must be exactly that, because it is the command's name.
  4. In Terminal, check Python is there: python3 --version. If macOS offers to install it, accept.
  5. Open Claude Code in any project and type /test-checklist. The first time, Claude asks what you would like to be called (the name is kept in ~/Ferramentas/html-salvavel/nome.txt) and offers to install the rest, asking before each thing:
    • the saving tool, in ~/Ferramentas/html-salvavel/;
    • the QA and Auditor agents, if you do not have them yet (then reopen Claude Code);
    • the Abrir HTML Salvável app ("Open Saveable HTML"), with its own icon, in ~/Applications. Drag it to the Dock.
💡 The Dock app: click it, pick the project folder that holds the test HTML and that is it: it opens the Terminal (leave it open) and the browser with the list. Next time it shows the list of recent projects. Two projects can be open at once: each one stays in its own Terminal window. If macOS asks to let the app control the Terminal, click OK.

4Keep it in one project only (optional)

If you want the skill to work in only one project, paste the test-checklist folder inside <project>/.claude/skills/, instead of your personal folder.

Careful in company projects: what sits inside the project may end up in the company's repository. If the skill is yours, prefer the personal install (step 3).
